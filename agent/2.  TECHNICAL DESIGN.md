# TÀI LIỆU 2: TECHNICAL DESIGN

## PHẦN 1: CÔNG NGHỆ CỐT LÕI (CORE TECHNOLOGIES) & BẢO MẬT (SECURITY)

### 1.1 Core Technologies

* **Platform:** C# .NET 8.0 (Windows Forms).

* **Architecture:**
  * Áp dụng kiến trúc Dependency Injection (DI) thông qua thư viện `Microsoft.Extensions.DependencyInjection`.
  * Các thành phần dùng chung (Security Manager, UI Manager, Agent Client...) được quản lý theo vòng đời Singleton.
  * Các Module được đăng ký theo vòng đời Transient nhằm đảm bảo khả năng mở rộng và giảm sự phụ thuộc giữa các thành phần.

* **Network Communication:**
  * Sử dụng `ClientWebSocket` để thiết lập kết nối song công (Full-Duplex) hỗ trợ WSS (TLS/SSL).
  * Hỗ trợ cấu hình bỏ qua xác thực chứng chỉ Self-signed trong môi trường Lab phục vụ mục đích học tập và thử nghiệm.
  * Luồng gửi dữ liệu được đồng bộ nhằm đảm bảo thread-safe khi nhiều thành phần gửi dữ liệu đồng thời.

* **UDP Broadcast (Auto Discovery):**
  * Agent lắng nghe UDP Broadcast tại cổng 8888 để tự động phát hiện Gateway trong mạng LAN.
  * Gateway gửi gói tin theo định dạng:

```
GATEWAY_ANNOUNCE|wss://ip:port
```

  * Agent tự động điền địa chỉ Gateway sau khi nhận được Broadcast hợp lệ.

* **Configuration Management**
  * Cấu hình được lưu trong `config.json`.
  * Agent tự động sinh Agent Identifier dựa trên Machine Name và MAC Address đang hoạt động nhằm giảm khả năng trùng lặp giữa các máy.

---

### 1.2 Concurrency & Resource Management

Hệ thống sử dụng mô hình lập trình bất đồng bộ (`async/await`) kết hợp với các tác vụ nền nhằm tránh chặn giao diện người dùng trong quá trình xử lý.

Các tác vụ định kỳ sử dụng `PeriodicTimer` để đơn giản hóa việc quản lý vòng đời và hỗ trợ hủy tác vụ an toàn.

Khi kết nối hoặc module kết thúc hoạt động, các tài nguyên được giải phóng nhằm hạn chế memory leak, handle leak và bảo đảm hệ thống hoạt động ổn định trong thời gian dài.

---

### 1.3 Security Design

#### Application Whitelisting

Agent chỉ cho phép khởi chạy các ứng dụng nằm trong danh sách Whitelist được Controller cấu hình. Các yêu cầu ngoài danh sách sẽ bị từ chối.

---

#### Sandbox & Path Validation

Mọi thao tác với hệ thống tệp đều được chuẩn hóa đường dẫn trước khi truy cập.

Agent chỉ cho phép truy cập các tệp nằm trong thư mục Sandbox hợp lệ nhằm giảm thiểu nguy cơ Path Traversal.

---

#### Explicit User Consent

Các chức năng có khả năng ảnh hưởng đến quyền riêng tư hoặc trạng thái hệ thống (Webcam, Screen Stream, Keylogger, Restart, Shutdown, Sleep...) yêu cầu người dùng xác nhận trước khi thực thi.

Nếu người dùng không phản hồi trong thời gian quy định, yêu cầu sẽ tự động bị từ chối.

---

#### Anti-DoS UI

Agent theo dõi các cửa sổ Consent đang hoạt động nhằm ngăn việc tạo nhiều hộp thoại trùng lặp trong thời gian ngắn, giúp giảm nguy cơ spam giao diện người dùng.

---

#### Visual Transparency

Trong quá trình Webcam hoạt động, Agent luôn hiển thị Overlay Red Dot ở chế độ Always-on-top nhằm thông báo rõ ràng cho người sử dụng về trạng thái ghi hình.

## PHẦN 2: CHI TIẾT THIẾT KẾ CÁC MODULE

### 2.1 AppModule (Application Management)

**Supported Commands**

* app_start
* app_stop
* app_list

**Design**

* Liệt kê các ứng dụng đang chạy có giao diện người dùng.
* Thu thập thông tin CPU và RAM của tiến trình tại thời điểm lấy mẫu.
* Chỉ cho phép khởi chạy ứng dụng nằm trong Whitelist.

---

### 2.2 ProcessModule (Process Management)

**Supported Commands**

* proc_list
* proc_kill

**Design**

* Thu thập thông tin tiến trình theo cơ chế xử lý song song nhằm giảm thời gian thống kê.
* Quản lý tiến trình thông qua Process ID (PID).
* Hỗ trợ timeout khi kết thúc tiến trình nhằm tránh chờ vô thời hạn.

---

### 2.3 StreamModule (Screen Monitoring)

**Supported Commands**

* screenshot
* screen_stream
* screen_stream_stop

**Design**

* Chụp màn hình bằng GDI+.
* Chuẩn hóa độ phân giải về 1280×720.
* Truyền dữ liệu theo mô hình hai giai đoạn:
  * Metadata (JSON)
  * Binary JPEG
* Khi nhận lệnh dừng hoặc mất kết nối, phiên Stream được kết thúc và giải phóng tài nguyên.

---

### 2.4 KeyloggerModule

**Supported Commands**

* keylog_start
* keylog_stop

**Design**

* Thu nhận sự kiện bàn phím ở mức hệ thống.
* Dữ liệu được lưu tạm trong bộ đệm và gửi định kỳ về Gateway nhằm giảm số lượng gói tin truyền.

---

### 2.5 FileModule

**Supported Commands**

* fs_list
* fs_get
* fs_put

**Design**

* Chỉ cho phép truy cập các tệp nằm trong Sandbox.
* Upload sử dụng cơ chế Chunking.
* Sau khi ghi hoàn tất, Agent tính toán SHA-256 để kiểm tra tính toàn vẹn của tệp.

---

### 2.6 WebcamModule

**Supported Commands**

* webcam_start
* webcam_stop

**Design**

* Thu hình bằng OpenCV.
* Chuẩn hóa độ phân giải 720p.
* Luôn hiển thị Countdown 10 giây trước khi bắt đầu ghi hình.
* Hiển thị Overlay Red Dot trong suốt quá trình Camera hoạt động.
* Camera được giải phóng ngay sau khi phiên ghi hình kết thúc.

---

### 2.7 PowerModule

**Supported Commands**

* Shutdown
* Restart
* Sleep
* Lock

**Design**

* Lock Screen được thực hiện ngay lập tức.
* Các thao tác Shutdown, Restart và Sleep yêu cầu User Consent trước khi thực thi.

---

## PHẦN 3: COMMUNICATION PROTOCOL

### Connection

* Agent gửi gói REGISTER sau khi kết nối thành công.
* Heartbeat (PING) được gửi định kỳ để duy trì trạng thái kết nối.

---

### Standard Payload

Các thông điệp JSON sử dụng cấu trúc thống nhất:

```json
{
  "type": "...",
  "command_id": "...",
  "module": "...",
  "action": "...",
  "params": { },
  "target_agents": [ ]
}
```

---

### Binary Transmission

Đối với dữ liệu lớn (Screen Stream, Webcam, File):

1. Metadata JSON
2. Binary Payload

Việc tách Metadata và Binary giúp giảm overhead khi truyền dữ liệu.

---

### Policy Update

Controller có thể gửi chính sách mới tới Agent để cập nhật:

* Application Whitelist
* Sandbox Path

Ví dụ:

```json
{
  "type":"policy_update",
  "params":{
      "app_whitelist":[
          "notepad",
          "calc",
          "word"
      ],
      "sandbox_path":"C:\\NewSandbox\\"
  }
}
```

## PHẦN 4: ERROR HANDLING

| Situation | Handling |
|------------|----------|
| Invalid JSON | Trả về thông báo lỗi cho Controller |
| Unknown Command | Từ chối yêu cầu và phản hồi lỗi |
| Permission Denied | Từ chối thực thi |
| User Reject | Hủy thao tác |
| Consent Timeout | Hủy thao tác |
| Connection Lost | Dừng các phiên đang hoạt động, giải phóng tài nguyên và thực hiện kết nối lại |
| File Not Found | Trả về trạng thái thất bại |

---

## PHẦN 5: DESIGN DECISIONS

| Design Decision | Reason |
|-----------------|--------|
| WebSocket | Hỗ trợ giao tiếp Full-Duplex thời gian thực |
| Dependency Injection | Giảm sự phụ thuộc giữa các thành phần, dễ bảo trì |
| Module-based Architecture | Dễ mở rộng chức năng |
| Binary Streaming | Giảm overhead khi truyền dữ liệu đa phương tiện |
| UDP Broadcast | Hỗ trợ Auto Discovery trong mạng LAN |
| Heartbeat | Phát hiện mất kết nối sớm |
| Consent Mechanism | Bảo vệ quyền riêng tư của người dùng |

| Category | Description |
|----------|-------------|
